# Known issues and operational limits

**Reviewed:** 19 November 2026  
**Code under review:** `a9de778cf0793a530ae6e347480f07820c17ab7d`  
**Scope:** observed behavior and source/schema limits. “Planned fix” is a recommendation unless marked completed; no future work is implied as authorized.

| ID | Severity | Issue | Impact | Workaround | Planned fix / status |
|---|---|---|---|---|---|
| KI-001 | Low — resolved | The CRAC equipment-health test assertion changed in `397797b`. Its earlier assumption that seeded CRAC had no active critical alert was false after the suite's prior `/alerts/run` test. | The old test was order-dependent and failed 19/20 despite correct dashboard behavior. | The test now creates and removes a dedicated recovered-fault fixture, and separately checks seeded CRAC status against active critical alerts. | Completed; frontend/API suite passed 37/37 on three fresh stacks. Preserve both assertions. |
| KI-002 | Low — resolved | `tests/integration/test_dashboard.py` originally used the whole data extent as its default window. A legacy compatibility fixture inserts a 2001 event; the API caps ranges at 31 days. | The standalone smoke script raised `DashboardError` after that fixture extended dataset extent. | The script now selects the latest 31-day interval ending at the latest stored fact; it returns 12 monitored assets on the H0 clone. | Completed in `abf44d1`; rerun is PASS. |
| KI-003 | Medium | Legacy telemetry has `source_id`, `received_at`, and `quality` as NULL. Operational readers exclude `BAD` and therefore treat NULL quality as usable/GOOD; no inferred provenance is available. | Reports cannot attribute legacy measurements to a connector or claim their receive time/quality was recorded. | Treat NULL as “legacy quality unknown” in provenance reporting; do not infer a source or receive timestamp. `v_telemetry_valid` retains these rows for compatibility. | Do not mass-backfill guesses. Add explicit provenance only when supported by independent evidence and a reviewed data change. |
| KI-004 | Low | `buildings.building_code` is nullable. | New source provisioning requires a registered code; existing buildings do not automatically have one. | Assign a stable external-safe code with `scripts/ingestion_admin.py register-building` before creating a source. | Keep nullable for legacy compatibility; add an operator inventory/check for buildings intended for source provisioning. |
| KI-005 / ISS-015 | Critical | The non-ingestion REST API and Socket.IO endpoints have no authentication or authorization. The ingestion route is protected by per-source keys. | Anyone with network access to the API can read operational data or invoke unprotected write/control routes. | Restrict API access to trusted networks and do not expose it publicly. | Add a reviewed authentication/authorization design covering REST and Socket.IO before customer deployment. |
| KI-006 | High | Compose publishes PostgreSQL (`DB_HOST_PORT`, default 5432) and Ollama (default 11434) on all host interfaces; PostgreSQL has no application-level authentication layer beyond its database password. | A reachable host port expands the attack surface; the database port is exposed by default. | Set strong DB credentials, firewall/restrict host networking, and choose unused host ports. Port variables change the number, not the bind address. | Make bind addresses configurable/restricted and remove public database exposure in a separately reviewed deployment change. |
| KI-007 | Medium | There is no scheduled freshness/gap job and no retention/expiry policy. | Silent source stoppage is not independently tracked as a gap; historical rows continue accumulating. | Check latest stored timestamps and source `last_received_at` operationally; plan backups/storage monitoring externally. | Define freshness expectations and retention ownership/policy before implementing jobs or deletes. |
| KI-008 / ISS-008 | Medium | Alert rules use a hardcoded UTC+2 offset and 08:00–18:00 working hours (`app/domain/alerts/alert_config.py`). | After-hours classification and time-of-day anomaly baselines can be wrong for sites in other time zones or operating schedules. | Use current rules only for the configured operating assumptions; review local timestamps before interpreting those rules. | Make IANA time zone and operating schedule explicit deployment/building configuration, with regression vectors. |
| KI-009 | Medium | Telemetry uniqueness is global on `(asset_id, metric_id, ts)` and does not include `source_id`. | Two sources reporting one series at the same timestamp conflict if values differ; identical values may be classified as duplicates. | Use one authoritative source per asset/metric/time series or coordinate timestamps and values upstream. | Define source precedence/aggregation and a reviewed key migration before supporting multi-source arbitration. Do not alter the current key implicitly. |
| KI-010 | Low | Legacy `POST /events` performs `to_regclass('public.uq_event_legacy_natural_key')` on each request to select a compatible conflict target. | Adds one catalog lookup per event write. | None required at current demo scale. | Cache migration capability at process start or use a stable compatibility path after rollout policy is established; retain pre-007 compatibility if required. |
| KI-011 | Low | Ingestion `CONFLICT` text is implementation wording, e.g. telemetry: “A different value is already stored for this asset, metric, and observed_at; first write was preserved.” Event/state wording differs. | Clients that parse prose may break when wording changes. | Branch on HTTP status and stable `reason_code: CONFLICT`; display `message` only to people. | Keep codes stable and treat message text as explanatory, not a machine contract. |
| KI-012 | Medium | There is no HTTP administration API. Source/building/key/mapping administration is via `scripts/ingestion_admin.py`. | Provisioning and revocation require repository/container/operator access. | Run the CLI in the API container with a least-privilege operator account; capture one-time keys in a secret manager. | Add an admin surface only after defining its auth, audit, and operator-authorization requirements. |
| KI-013 | Medium | The API and background detector run as a single Uvicorn process; no distributed scheduler/leader election is present. | Horizontal replicas could run duplicate background detection or broadcasts. | Run one API replica for this deployment. | Define multi-instance scheduling and idempotent broadcast ownership before scaling horizontally. |
| KI-014 | High for integration readiness | No vendor connector or simulator connector is implemented. The tested first batch was manually submitted to the Core API. | The system does not yet poll, subscribe to, buffer, retry, or translate a real device/vendor feed. | Use the documented batch contract and manually provision source/mappings for controlled tests only. | Build a separately scoped connector after vendor protocol and operational requirements are approved. |
| KI-015 | Medium | LLM mode depends on local Ollama and a downloaded model. When the endpoint is unavailable, the tested E2E path falls back to deterministic evidence-grounded text and states that the language model was unavailable. | Model-generated explanations are unavailable during Ollama/model outage. The tested fallback is grounding-checked but not a semantic-accuracy guarantee. | Keep LLM optional; use the deterministic fallback and review cited evidence. | Successful live-model inference was **NOT TESTED** in this item 0.7 run. Verify model download, response, timeout, and recovery on the target deployment before claiming LLM readiness. |
| KI-016 | Low | The H0 dashboard snapshot and migrated API differed in one floating-point final digit for average zone temperature (`17.872061855670097` vs `17.8720618556701`). | Byte/strict-float comparisons report a difference despite an approximately `3.6e-15` numerical delta. | Compare within an explicit numeric tolerance while preserving exact comparisons for identifiers, counts, enums, and timestamps. | Document a per-field comparison policy; do not round the API value silently without a contract decision. |

## Release boundary

These issues describe known limitations; they are not authorization to expand architecture. The live/shared database remains unmigrated. See [`docs/RELEASE_CHECKLIST_v0.1.md`](docs/RELEASE_CHECKLIST_v0.1.md) for release gates and their current PASS/FAIL/NOT TESTED state.
